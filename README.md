# Племенная книга — официальный сайт

Информационный лендинг проекта **«Племенная книга»** для заводчиков кошек и собак.

Автор проекта — **Лариса Молчанова**.

## Страницы

- `index.html` — главная: преимущества, две редакции, вопросы, инструкции, история проекта.
- `cats.html` — страница племенной книги для кошек.
- `dogs.html` — страница племенной книги для собак.
- `styles.css` — единое оформление и адаптация под телефоны.
- `guide.html` — справочный центр: подбор инструкции под задачу.
- `install.html` — установка на Windows, Android, iPhone и проверка офлайна.
- `records.html` — первые карточки, вязки, помёты и ветучёт.
- `backup.html` — создание JSON, восстановление, перенос между устройствами.
- `update.html` — безопасная проверка и установка обновлений.
- `troubleshooting.html` — пустая база, проблемы с установкой, JSON и связь с автором.
- `privacy.html` — политика конфиденциальности, охватывает статический сайт и текущие бесплатные книги.
- `terms.html` — пользовательское соглашение для бесплатных редакций.
- `favicon.svg` — значок сайта.
- `robots.txt`, `sitemap.xml` — исходные настройки для поисковой индексации.
- `.nojekyll` — сайт не нуждается в обработке Jekyll.

Сайт полностью статический, не использует сторонние библиотеки, шрифты, рекламные скрипты или аналитические счетчики. На нём **нет форм ввода данных питомника, регистрации и оплаты**.

## Как опубликовать на GitHub Pages

1. Открыть [Settings → Pages](https://github.com/domin0nml-crypto/plemennaya-kniga-site/settings/pages).
2. В разделе **Build and deployment** выбрать **Source: Deploy from a branch**.
3. Указать **Branch: main**, **Folder: /(root)**, нажать **Save**.
4. Дождаться публикации и открыть предполагаемый адрес:
   **https://domin0nml-crypto.github.io/plemennaya-kniga-site/**.
5. Проверить переходы на книги, инструкции и оба раздела на телефоне.

**Важно:** в репозитории находятся только файлы рекламного сайта. Сами программы и данные пользователей размещаются отдельно и этим репозиторием не меняются.

## Что обновить при покупке домена

В HTML-файлах сайта (`index.html`, `cats.html`, `dogs.html`, `guide.html`, `install.html`, `records.html`, `backup.html`, `update.html`, `troubleshooting.html`, `privacy.html`, `terms.html`) нужно заменить канонические ссылки (`rel="canonical"`, `og:url`, URL внутри JSON-LD). В `sitemap.xml` обновить `loc`, а в `robots.txt` — адрес карты сайта. Затем подключить новый домен к хостингу и Яндекс Вебмастеру. Не забудьте проверить внутренние ссылки и карту сайта после переезда.

**Не включать аналитику в самих книгах только ради статистики сайта.** Сайт можно анализировать отдельно, не помещая сторонние скрипты на страницу с локальной базой.

## Юридические документы и вопросы перед запуском платных функций

На сайте опубликованы два документа — `privacy.html` и `terms.html` (редакция 14.11.2026). Они описывают текущие бесплатные редакции, локальные записи, отдельную аналитику Яндекс Метрики внутри книг и обращения в поддержку.

Публикация документов **не равна полному выполнению 152-ФЗ**. До расширения сбора персональных данных необходимо проверить основания обработки, требования к отдельным согласиям, необходимость уведомления Роскомнадзора, взаимодействие с хостерами и аналитикой, в том числе требования локализации и трансграничной передачи.

Особое техническое замечание: встроенная в публичные книги Яндекс Метрика работает в контексте страницы с локальной IndexedDB. Перед заявлениями об абсолютной конфиденциальности нужно дополнительно провести аудит изоляции сторонних скриптов. Лендинг пока не содержит счётчиков.

Контакт по вопросам персональных данных сейчас указан через сообщения ВК `https://vk.ru/breed_cat`. При появлении специального рабочего email нужно добавить его в обе страницы. После технических и юридических доработок желательно добавить ссылки на документы непосредственно в интерфейс самих книг.

Перед запуском Pro, оплаты, авторизации или публичной синхронизации документы необходимо переработать; коммерческие условия здесь не оговорены.

## Принципы публикаций

- Не обещать абсолютную защиту от утечек или потери данных.
- Пояснять, что офлайн-работа доступна после первой загрузки и сохранения файлов браузером.
- Честно указывать бесплатные лимиты: 20 самостоятельных карточек и 4 помёта.
- Не публиковать цены Pro, пока продажи не запущены.
- Не добавлять реальные истории пользователей без разрешения.
- Следить за актуальностью ссылок и возможностей каждой редакции.
