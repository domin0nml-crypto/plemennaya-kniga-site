Резервная копия

Как сохранить и перенести базу

Самая важная инструкция для ваших записей: резервный файл JSON, восстановление, перенос и ошибки, которых легко избежать.

На этой странице: Что такое JSON · Сохранить · Восстановить · Перенести · Безопасность

1. Что такое JSON и зачем он нужен

JSON — обычный файл с резервной копией записей питомника. В него входят данные книги на момент создания файла: животные, связанные записи и другие сведения, которые программа сохраняет в базе. Это не сама программа и не файл для установки.

По умолчанию записи хранятся внутри браузера, а не в вашей папке «Документы». JSON позволяет получить отдельную копию, перенести её на другой телефон или компьютер и восстановить данные после сбоя.

Главное правило: восстановление JSON в обеих текущих редакциях заменяет текущую локальную базу целиком. Оно не складывает две разные базы вместе. Перед любым импортом обязательно экспортируйте текущие записи.

2. Как сохранить резервную копию

  1. Откройте свою кошачью или собачью книгу в том браузере или приложении, где уже есть записи.
  2. Нажмите «☰ Меню» → «Настройки».
  3. В блоке «Резервные копии» нажмите «Скачать JSON».
  4. Дождитесь загрузки файла. На телефоне посмотрите «Загрузки» или диалог сохранения/передачи. Убедитесь, что файл действительно появился и не равен нулю байт.
  5. Назовите копию так, чтобы вы узнавали дату и редакцию: например, cats-2026-11-14.json или dogs-2026-11-14.json. Не меняйте содержимое вручную.
  6. Скопируйте файл в другое надёжное место: на компьютер, внешнее хранилище или в личный защищённый облачный диск. Не ограничивайтесь папкой «Загрузки» того же телефона.

Если по кнопке показывается подготовленная резервная копия и вариант «Сохранить / поделиться», используйте подходящий способ сохранения на вашем устройстве. На разных браузерах этот экран может отличаться.

Когда создавать JSON?

После переноса большой базы, перед обновлениями, до восстановления другого файла, перед сменой телефона и регулярно в процессе работы — особенно после появления помёта и новых записей.

3. Как восстановить записи из JSON

  1. Откройте книгу той же редакции, из которой сделан файл: кошачий JSON — в кошачью, собачий — в собачью.
  2. Если в текущем браузере уже есть какие-либо записи, сначала нажмите «Скачать JSON» и сохраните отдельную копию на случай ошибки.
  3. В «Настройках» нажмите «Восстановить из JSON» и укажите нужный файл.
  4. Прочитайте предупреждение о замене базы. Подтверждайте действие только если действительно хотите заменить текущие записи содержимым выбранного файла.
  5. После завершения откройте раздел «В питомнике» и проверьте количество животных, помётов, связи и несколько записей.
  6. Не удаляйте исходный JSON сразу после импорта. Храните резервную копию независимо от устройства.

В программе предусмотрен раздел «Восстановление после импорта» с возможностью возврата предыдущего состояния, если оно сохранилось. Не рассчитывайте на него как на единственную страховку: лучше иметь отдельный JSON, созданный до действий.

4. Как перенести книгу с телефона на компьютер и обратно

  1. На устройстве А, где находится нужная актуальная база, экспортируйте JSON по инструкции выше.
  2. Передайте файл на устройство Б удобным способом: через кабель, личное файловое хранилище или другое надёжное средство передачи.
  3. На устройстве Б откройте правильную редакцию книги в обычном браузере и, если там есть своя история, сначала сохраните её отдельным JSON.
  4. Нажмите «Настройки» → «Восстановить из JSON», выберите переданный файл, подтвердите замену базы.
  5. Проверьте карточки и помёты на устройстве Б. Дальше базы на двух устройствах не будут обновлять друг друга автоматически.

Пример. В понедельник вы заполнили помёт на телефоне и перенесли JSON на компьютер. Во вторник записали новые веса на телефоне. На компьютере эти веса не появятся, пока вы снова не экспортируете и не восстановите свежий файл.

Если вы параллельно редактировали базу и на телефоне, и на компьютере, простой импорт одного JSON сотрёт отличающиеся изменения на принимающем устройстве. Автоматического слияния в общедоступных редакциях пока нет.

5. Чего не делать с резервными копиями

  • Не отправляйте JSON в публичные чаты и комментарии: внутри могут находиться данные о животных, владельцах и покупателях.
  • Не восстанавливайте кошачий файл в собачьей книге и наоборот.
  • Не храните единственный экземпляр JSON на том же устройстве, которое собираетесь менять или очищать.
  • Не считайте перенос копии синхронизацией: после экспорта базы расходятся, если вы редактируете их по отдельности.
  • Не очищайте данные сайта при устранении технических неполадок, пока не создали и не проверили резервную копию.
